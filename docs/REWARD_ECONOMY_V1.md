# Reward Economy V1 — 현행 지급 규칙 전수 기록 (2026-08-17)

이 문서는 **현재 코드에 실제로 구현된 값만** 기록한다. 수치 변경 제안이
아니라 현황 스냅샷이며, **모든 수치 변경은 운영자 승인 전 금지**다.
근거는 전부 소스 실측(`src/hooks/useStudent.js`, `src/utils/rewardEngine.js`,
`src/utils/matchGame.js`).

별 지급은 `grantReward(amount, dedupKey)` 단일 경로를 통해서만 일어난다
(2026-07-28 `21bce52`에서 통합). Reward V1이 추가한 `grantLedgerReward()`도
이 함수를 그대로 호출하며 별도 경로를 만들지 않는다.

---

## 1. 신규 보상 (Reward System V1, 2026-08-15~17)

`src/utils/rewardEngine.js`의 `REWARD_STARS`가 단일 진실 원천이다.

| 학습 행동 | 별 | idempotency source_id | 지급 빈도 |
|---|---|---|---|
| 단어 학습 세션 정상 완료 | **+1** | `daily-words:{날짜}` | 하루 1회 |
| 쓰기 학습 정상 완료 | **+2** | `daily-writing:{날짜}` | 하루 1회 |
| 단어(입실) 시험 정상 완료 | **+2** | `entrance-test:{testId}` | 시험 1개당 1회 (영구) |
| 틀렸던 단어 재도전 성공 | **+1** | `spelling-review:{날짜}:{wordId}` | 단어당 하루 1회 |
| 하루 학습 목표(4/4) 완료 | **+3** | `daily-goal:{날짜}` | 하루 1회 |

### streak 보너스

`STREAK_BONUS = { 3: 2, 5: 3, 7: 5 }` — V1은 이 3단계뿐이며 추가 단계 없음.
source_id는 `streak:{날짜}:{연속일수}`.

| 연속일 | 3일 | 5일 | 7일 | 그 외(1·2·4·6·8·14·30…) |
|---|---|---|---|---|
| 보너스 | +2 | +3 | +5 | 0 |

- 하루 목표를 완료한 날만 streak로 인정된다(`calcStreak`는 4/4 달성일만 센다).
- 하루에 여러 번 공부해도 streak는 하루 1회만 증가한다.
- **정책 주의**: streak가 끊긴 뒤 다시 3일에 도달하면 날짜가 다르므로 새 키가
  되어 +2가 다시 지급된다. 이는 "재도전 장려"로 해석되지만 의도된 정책인지
  운영자 확인이 필요한 지점이다(현재 코드 동작을 그대로 기술).

### 레벨 (별 소비 없음, 누적 기준)

| Level | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 누적 별 | 0–19 | 20–49 | 50–99 | 100–199 | 200+ |

## 2. 레거시 보상 (기존, 이번 작업에서 한 줄도 변경하지 않음)

| 트리거 | 별 | dedup 키 | 반복성 |
|---|---|---|---|
| 4/4 라운드 완료 (`MISSION_BONUS_STARS`) | **+10** | 라운드 signature | **하루 중 라운드마다 반복 지급** |
| 매치 게임 정답 (`STAR_PER_CORRECT`) | **+10** / 정답 | `matchgame:{sessionId}:{round}:{wordId}` | 게임 1세션 5라운드 = 최대 +50, **세션 재시작 시 반복** |
| 기프트박스 중복 스티커 (`DUPLICATE_BONUS_STARS`) | **+20** | 뽑기마다 새 키 | 중복 당첨마다 반복 |
| 레벨업 미션 클리어(같은 단어 3연속 정답) | +3 | `mission-clear:{wordId}` | 단어당 **영구 1회** |
| 발음 연습 성공 | +1 | `pronunciation:{wordId}:{날짜}` | 단어당 하루 1회 |
| 쓰기 콤보 3/5/10 (`SPELLING_COMBO_BONUS`) | +1/+2/+3 | `spelling-combo:{wordId}:{combo}:{날짜}` | 콤보 1회분 최대 +6 |

### 레거시 +10과 신규 +3의 공존 조건

같은 트리거(4/4 라운드 완료)에서 **둘 다** 발동하지만 키 체계가 달라 서로
간섭하지 않는다:

- 레거시 `+10`: 키가 **라운드 signature** → 같은 날 2·3라운드째에도 매번 재지급
  (기존에 검증된 게임 경제, 운영자 결정으로 **유지**).
- 신규 `+3`: 키가 **날짜** → 그날 첫 4/4에서만 1회.

즉 하루 첫 라운드는 `+10 +3 = +13`, 같은 날 두 번째 라운드부터는 `+10`만.
이 동작은 `scripts/testRewardFlow.mjs`가 별 델타 실수치로 고정한다
(1라운드 +18 = 발음5 + 레거시10 + 신규3, 2라운드 +15 = 발음5 + 레거시10).

## 3. 예상 별 획득량

**세션 정의**: 한 학습 라운드(단어보기5 / 예문듣기5 / 퀴즈5 / 발음5 = 4카테고리).
매치 게임·시험은 별도 화면이므로 세션 외로 계산한다.

### 세션당 (신규 보상만)

| | 최소 | 평균 | 최대 |
|---|---|---|---|
| 그날 첫 세션 | 0 (미완료) | +4 (세션1 + 목표3) | **+6** (세션1 + 쓰기2 + 목표3) |
| 같은 날 2번째 이후 세션 | **0** | 0 | 0 (전부 날짜 키) |

### 세션당 (레거시 포함)

| | 최소 | 평균 | 최대 |
|---|---|---|---|
| 그날 첫 세션 | 0 | 약 +21 (발음5 + 레거시10 + 신규6) | +27 (콤보 +6 포함) |
| 2번째 이후 세션 | 0 | 약 +15 (발음5 + 레거시10) | +21 |

### 하루 (신규 보상만)

| | 값 | 구성 |
|---|---|---|
| 최소 | **0** | 학습 미완료 |
| 평균 | **+6 ~ +9** | 세션1 + 쓰기2 + 목표3 (+ 오답 회복 1~3) |
| 최대(현실적) | **+18** | 세션1 + 쓰기2 + 시험2 + 오답회복5 + 목표3 + streak 도달일 5 |

오답 회복은 **일일 상한이 없다** — 그날 복습 큐에 있던 서로 다른 단어 수만큼
+1씩 누적된다(단어당 하루 1회). 복습 큐 크기가 사실상의 상한이다.

### 하루 (레거시 포함, 전체)

| | 값 | 비고 |
|---|---|---|
| 최소 | 0 | |
| 평균 | **+25 ~ +40** | 라운드 2회 + 발음 + 신규 |
| 최대 | **상한 없음** | 매치 게임 반복(세션당 +50) + 기프트박스 중복(+20/회)이 횟수 제한 없음 |

**핵심 결론**: 별 인플레이션 리스크는 신규 보상(하루 최대 +18)이 아니라
**레거시 경로**(매치 게임 +10/정답 무제한 반복, 기프트박스 중복 +20)에 있다.
신규 보상은 전부 날짜/이벤트 키로 하루 1회씩 묶여 있어 구조적으로 상한이 있다.

## 4. 중복 지급 가능 경로 점검

### 신규 보상 — 중복 위험 없음 (테스트로 고정)

4중 방어: ① `hasRewardEntry` 사전 체크 ② `appendRewardEntry`가 `patch()`
updater 안에서 `prev` 기준 재검사(같은 tick 중복 안전) ③ 기존 `grantReward`의
`starGrantLog`가 동일 키로 2차 차단 ④ 서버 테이블 적용 시 `idempotency_key`
전역 UNIQUE.

- 새로고침 / 뒤로가기 / 재로그인 / 같은 tick 이중 호출 / API 재시도: 지급 0 (실측)
- 오답 회복은 `clearSpellingReviewWord`와 `recordSpellingAnswer` **두 경로가
  같은 키**를 써서 교차 호출 시에도 1회만 지급(실측)
- 시험은 서버 저장 **성공 시에만** 호출되고 키가 `testId`라, 재시도 버튼으로
  재제출해도 추가 지급 0

### 레거시 — 기존부터 존재하는 반복 지급 경로 (이번 범위 밖, 변경 금지)

| 경로 | 성격 | 판단 |
|---|---|---|
| 매치 게임 +10/정답 | 세션 재시작마다 새 `sessionId` → 반복 획득 | **의도된 게임 보상**이나 실질 상한 없음 — 운영자 검토 대상 |
| 기프트박스 중복 +20 | 뽑기마다 `Date.now()+random` 키 → 항상 신규 | 중복 스티커 보상 설계상 의도 |
| 4/4 라운드 +10 | 라운드 signature → 하루 반복 | 문서화된 의도(missions repeat all day) |
| 발음 `pronunciation-unidentified` +1 | `Date.now()+random` 키 → 매번 지급 | **레거시 취약점** — `word.dbId`가 없는 단어에서만 발생. 별도 정리 과제 |

이 4개는 전부 Reward V1 이전부터 존재하던 동작이며, 운영자 결정(기존 동작
유지)에 따라 이번 작업에서 손대지 않았다.
