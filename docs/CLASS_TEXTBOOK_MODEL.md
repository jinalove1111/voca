_작성 2026-08-11 (93차). 이 문서는 "학생이 어떤 교재를 쓸 수 있는가"와
"누가 입실시험 대상인가"를 정의하는 **단일 기준서**입니다. 2026-08-10~11에
같은 버그가 형태를 바꿔 세 번 재발한 뒤, 개념이 섞여 있던 것이 원인으로
확인되어 작성했습니다._

## 5개 개념 — 절대 섞지 말 것

### 1. Class (반) — `classes` / `students.class_id`

학생이 **실제로 소속된 사람 그룹**. 예: `MS Advanced Class`, `Pre-Middle School`.

- 학생 1명은 사람 반 **정확히 하나**에 속한다 (`students.class_id`).
- 반은 표시·관리 단위이지 **콘텐츠 소유자가 아니다**.
- 사람 반은 보통 유닛이 0개다 → **관리자가 사람 반으로는 시험을 낼 수 없다**
  (출제 단어 0개 → "시험 시작" 버튼 비활성). 이게 이번 사고의 구조적 배경.

한편 `class_type='textbook'`인 반은 **교재 컨테이너**다 — 사람이 소속되지
않고 유닛/단어만 담는다. 예: `고1 능률 민병천`, `중2 YMB 박준원`.
**시험은 사실상 항상 이 컨테이너 반으로 열린다.**

### 2. Class Default Textbook (반 기본 교재) — `class_textbooks`

"이 반 아이들이 기본적으로 쓰는 책"을 반 단위로 연결한 것.

- **용도: 학생 화면의 교재 선택기 노출 목록**(`App.jsx` `textbookOptions`).
- **입실시험 판정에는 쓰지 않는다** (아래 5번 참고). 반에 걸려 있다는 이유만으로
  그 반 전원을 시험 대상으로 삼으면, 실제로는 다른 책을 배정받은 학생까지
  끌려 들어온다(실측: 고1 능률 민병천 8명 → 15명, Pre-Middle 9명 오노출).

### 3. Individual Student Textbook Assignment (학생별 교재 배정) — `student_class_assignments`(SCA)

**특정 학생 1명에게** 그 교재의 사용 권한을 준 것. 이게 **권위 있는 기준**이다.

⚠️ 이 테이블 한 행에는 **독립된 두 축**이 있다:

| 컬럼 | 도입 | 의미 |
|---|---|---|
| `class_id` | v2.9 | 그 행의 컨테이너 반 |
| `textbook_id` | v3.1 | 실제 배정된 교재 |

`setPrimaryTextbook`은 **`textbook_id`만 갱신하고 `class_id`는 예전 값을 그대로
둔다**(사람 반 불변 전환). 그래서 한 행이 두 축에서 서로 다른 반을 가리키는
상태가 **정상적으로** 존재한다(실측 56행).

```
실측 예 — Jinaa의 primary 배정 행
  class_id    = Presentation 6        ← 옛 축(그대로 남음)
  textbook_id = "고1 능률 민병천"        ← 실제 배정
```

**따라서 두 축을 모두 봐야 한다.** 하나만 보면 91차 버그가 재발한다.

### 4. Current Textbook (현재 학습 교재) — `students.current_unit_id`

학생이 **지금 펴 놓은 책**. 유닛의 소유 반을 거슬러 올라가면 나온다.

- 단어/유닛 로딩(학습 계층)은 이 값을 따라간다.
- **입실시험 판정에는 쓰지 않는다.** 학생은 교재를 오가며 공부한다 —
  김보민은 지금 `고1 6월 학평`을 보고 있지만 `고1 능률 민병천`도 배정돼 있어
  **두 시험 모두 대상**이어야 한다. 오늘 연 책으로 판정하면 이 케이스가 깨진다.

### 5. Entrance Exam Eligibility (입실시험 대상) — `src/utils/entranceEligibility.js`

**단일 진실 공급원.** 학생 화면과 관리자 화면이 **반드시 같은 함수**를 쓴다.

```
학생의 조회 범위 = 다음 반 id의 합집합(중복 제거)
  A. students.class_id                              → source: CLASS_MEMBER
  B. student_class_assignments.class_id             → source: INDIVIDUAL_CLASS
  C. B행의 textbook_id가 가리키는 교재의 소유 반      → source: INDIVIDUAL_TEXTBOOK

시험(entrance_tests.class_id)이 이 범위에 있으면 대상.
```

**판정에 절대 넣지 않는 것** (반증 테스트로 고정됨):

| 넣으면 안 되는 것 | 이유 |
|---|---|
| `class_textbooks` (2번) | 배정 없는 학생까지 대상이 됨 |
| `current_unit_id` (4번) | 교재를 오가는 학생이 누락됨 |
| 학년·반 이름 문자열 | 중2 학생도 고1 교재를 배정받으면 봐야 함 |

## 운영 원칙 (2026-08-11 운영자 확정)

> **학생의 반 ≠ 학생이 공부할 수 있는 모든 교재.**

- 중2 학생도 필요하면 고1 교재를 공부할 수 있다.
- Pre-Middle 학생도 필요하면 고1 교재를 쓸 수 있다.
- **반을 옮기지 않고** 학생별로 추가 교재를 쓸 수 있어야 한다.
- Pre-Middle 9명 중 1명만 고1을 공부한다면 **그 1명에게만** 고1 시험이 보여야 한다.
- 학년/반 이름만 보고 접근을 막지 않는다.

## 실무 규칙

### 특정 학생에게 다른 학년 교재를 주려면
관리자 → 학생 관리 → 해당 학생 → 📚 교재 관리 → 교재 배정.
**반을 바꾸지 않는다.** SCA 행 1개가 생기고 그 학생만 대상이 된다.

### 반 전체가 새 교재로 넘어가면
`class_textbooks`에 연결(선택기 노출) **+ 학생별 배정**. 배정이 없으면
시험 대상이 되지 않는다 — 이건 버그가 아니라 확정된 정책이다.

### 관리자 "반 전체 N명"
`fetchEntranceRosterForClass()` — 위 A∪B∪C에서 아카이브/중복/QA 계정을 뺀 값.
학생 화면 대상 집합과 **1:1로 일치**해야 하며, 회귀 테스트가 이를 강제한다.
