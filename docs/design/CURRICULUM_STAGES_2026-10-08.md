## 0. 읽는 법·전제
- **기간은 운영 계획**이다. 기간이 지났다고 자동 승급하지 않는다(진급 검토는 설계안 §11: 서로 다른 회차 2회 + 상황 바꾼 과제 1회, 교사 관찰). 교재 번호·나이·단어 수만으로 학생 레벨을 단정하지 않는다.
- **상태 표기**: `구현` = 앱에서 실제로 할 수 있음(QA 전용) · `회차만` = 이야기 회차·문항은 있으나 Unit 화면으로 묶이지 않음 · `미제작` = 콘텐츠 없음(기존 예문을 복사해 이름만 바꿔 채우지 않는다).
- **수행 수준 사다리**(`PERFORMANCE_LEVELS`, 말하기·쓰기 따로): 입문(단어·짧은 구 / 글자·단어) · 기초(한 문장 / 문장 틀·한 문장) · 발전(질문·응답 / 자기 문장 2~3개) · 확장(이유·과거·계획 / 연결된 짧은 글) · 발표(구성·요약·후속 질문 / 발표 원고). 이는 **Unit이 요구하는 수행**이며 학생의 영구 레벨이 아니다. 한 학생이 말하기 '발전'·쓰기 '기초'일 수 있고, 그때 교사는 같은 주제의 인접 단계 Unit을 영역별로 다르게 고른다(§3).
- **지원 단계**(모범과 함께 / 단서로 / 혼자 / 새 상황에서)는 수준이 아니라 도움의 양 — 위 사다리와 별개 축.
- 특정 출판사 교재의 문장·이미지·단원 구성을 복제하지 않는다. 학습 효과를 주장하지 않는다.
- 이 세션에서 **구현된 것**: 수행 수준·교육 프로필 데이터 계약, 과정 → 단계 → Unit 선택 화면, Unit 1·2 프로필, 말하기 → 쓰기 연결. **문서에만 있는 것**: 아래 단계표의 Unit 대부분(미제작).

## 3. Presentation 9개월 — 3단계 (PR1–PR3) · 전부 미제작
**원칙**: 발표 암기 아님 — 자료 이해 → 생각 구성 → 전달 → 질문 응답(설계안 §6). 발표 시간은 관찰 가안; 긴 말·시선·외향성·억양 모방은 숙달 지표 아님. 녹음은 기기 내 선택.
**회화와의 병행 선수 능력(기간 아님)**: 익숙한 주제의 질문을 이해해 자기 정보로 답하고 되묻기 1회, 준비 없는 작은 변화에 대응, 2~3문장 이어 말하기, 80단어 이내 짧은 글 핵심 찾기, 자기 문장 1~2개 쓰기 — 이 행동이 "혼자"로 관찰되면 회화 후반 블록과 PR1 병행 가능.
**수행 수준 '발표'와의 관계**: 구성·요약·후속 질문·발표 원고 네 요소가 PR1부터 모두 등장하되 도움 정도가 다르다 — PR1=구성(교사 제공 틀), PR2=구성+요약(순서·비교), PR3=후속 질문(미리 외우지 않은 질문)+발표 원고(초안→피드백→개정). 즉 PR 단계 = 같은 수행 수준에 대한 지원 단계 축소 과정.

## 4. Reading & Grammar 12개월 — 4단계 (RG1–RG4) · 전부 미제작
**앞 단계 연결점**: ① 파닉스 P4 "해독 글 의미 확인" → RG1 "문자 그대로 정보"(해독 불안정 학생은 RG1 글을 짧게 + 파닉스 보강 별도) ② 회화 Unit 1·2의 읽기 지문(≤80단어, 근거 문항 3)과 문형 관찰(noticing 2, 의미 중심)은 **RG 이전 "읽기·문법 맛보기"**로 기록 — RG1 선수 능력 관찰 자료로 재사용, 재제작 없음 ③ PR3 근거 선별 → RG3 근거 인용.
**문법 원칙**: 의미·사용 중심(관찰 → 통제 연습 → 의미 사용). 현재완료·수동태·관계절·to부정사·동명사는 달 배정 없음 — 이해·기초 문장 구성 확인 후 준비 과제로만.
**텍스트 길이 가안**: RG1 60~120 / RG2 100~180 / RG3 150~250 / RG4 200~350 단어(단어 수만으로 배정하지 않음).

## 9. 첫 구현 — 인접 두 단계(C1 기초 → C2 발전), 같은 목표 `asking-info`, 같은 상황 가족(교실에서 물건 찾기)

- **난이도 차이가 실제로 드러나야 하는 곳**: 말하기 — C1은 묻기 또는 답하기 한 쪽만 혼자(기초) / C2는 질문 생성 + 짧은 답 + 되묻기 3턴, 회상 단계에 미아의 되묻기에 **다시 답하는 후속**(`followUp`, 2차 답 확인) 포함(발전). 쓰기 — C1 `w-u2-under` 틀 완성 1문장 / C2 `w-c2-find` 어디에 없고·어디에 있는지 **자기 문장 2~3개**(모범은 비교용).
- 상태: 데이터 제작(교육 설계 담당 초안 → 리드 확정) → **교사 검수 대기**. 화면은 기존 템플릿 그대로(새 화면 없음, `followUp`만 UnitSpeaking에 추가).

### 10.4 News Class 수준 구분 제안 — N1 · N2 · N3 (제안, 전부 콘텐츠 준비 중)
**병행 수강 원칙**: News Class는 다른 과정의 레벨과 독립이다. 어떤 과정의 어느 레벨이든 병행할 수 있다고 가정하지 않고, 자동 배정·자동 승급은 없다. 수준 구분 기준은 기간이나 학년이 아니라 지문 길이, 어휘(고빈도 → 주제어 → 추상어), 이해(사실 찾기 → 추론 → 요약) 수행이다. 지문 길이는 단어 수만으로 배정하지 않는다.

| 레벨(제안) | 선수 능력(교사 관찰) | 목표 표현·어휘·문법 | 지문·이해 수준 |
|---|---|---|---|
| N1 | 짧은 글(약 80단어)의 누가·어디·언제를 찾는다 | 고빈도 어휘와 사건 표현, 과거·현재 시제 구분 | 매우 짧은 기사형 글, 사실 찾기 |

### 10.6 화면 진입 규칙
1. 홈 Speaking, 홈 Writing, 오늘의 학습은 모두 같은 흐름으로 들어간다: **과정 → 레벨 → 목록**.
2. 레벨 목록의 항목은 실제 Unit(7활동) 또는 이야기 연습(회차) 중 하나다. 주제 분류는 항목 카드의 라벨이다.
3. 콘텐츠가 없는 과정·레벨은 '콘텐츠 준비 중'으로 비활성 표시한다. 기존 예문을 복사해 채우지 않는다.
4. 과정·레벨 선택은 **세션 상태**일 뿐이다. 영구 레벨 저장, 자동 배정, 자동 승급, 자동 채점은 없다.

7. News Class는 병행 과정이므로 다른 과정의 레벨 선택과 독립으로 선택된다.
8. 모든 레벨 이름에 '제안' 표시를 붙인다(학원 확정 전).

## 12. (231차, 2026-10-09) Grammar 통합 — 과정이 아닌 Unit 안의 문법, 공통 데이터 연결 (가정 명시 · 운영자 확인 전)
_이 절은 §0~§11을 지우거나 고치지 않고 덧붙인다. 운영자가 요청한 "Grammar requirements"의 원문은 세 번 전달 시도에서 모두 본문 없이 끊겨 **수신하지 못했다**. 따라서 이 절은 운영자가 이미 말한 내용(§10 서두의 "Grammar는 과정이 아니라 각 과정 Unit 안에 연결된다")에서 도출되는 최소 범위만 다루며, 아래 가정은 모두 운영자 확인 전이다._

### 12.0 전제·가정 (요구사항 원문 미수신 · 운영자 확인 전)
1. **[가정]** Grammar는 과정이 아니다. 각 과정의 Unit 안에 연결된다(§10.1 과정표, `courseModel.js` Reading 과정 `focusKo`의 "(문법은 각 단원 안에서)"). 별도 Grammar 반·레벨 목록을 만들지 않는다.
2. **[가정]** 문법 원칙은 §4의 "의미·사용 중심(관찰 → 통제 연습 → 의미 사용)"을 그대로 쓴다. 용어 암기·규칙 설명 위주로 바꾸지 않는다.
3. **[가정]** 자동 채점, 점수, 숙달 판정, 새 DB 테이블·컬럼, 영구 저장이 없다(§10.6 4번과 같은 세션 상태 원칙). 학생 응답은 교사 관찰 보조일 뿐이다.
4. **[가정]** 학원이 레벨 이름을 확정하기 전까지 모든 레벨 라벨에 '(제안)'을 유지한다(§10.1, §11.0).
5. **[가정]** 새 문법 콘텐츠를 만들지 않는다. 이미 있는 Unit의 문형 활동(관찰 2 + 선택 문항 3, 다답 지원)만 연결한다. 회차(ep01~ep10)에는 문법 항목이 없으므로 회차를 통한 문법 진입은 '콘텐츠 준비 중'이다.

### 12.1 문법이 사는 자리
- Unit의 활동 순서는 vocab → listening → reading → speaking → **grammar** → writing → review이다. 문법은 말하기 뒤, 쓰기 앞에 온다.
- 흐름은 **관찰(noticing 2) → 선택(선택 문항 3, 정답이 둘 이상일 수 있는 문항은 다답 지원) → 쓰기**로 이어진다. 앞 두 단계는 문형 활동이 맡고, 의미 사용(자기 문장 쓰기)은 같은 Unit의 쓰기 활동이 맡는다.
- 문법은 같은 Unit의 말하기 문장에서 나온 문형만 다룬다. 새 상황이나 새 문형을 문법 활동에서 처음 도입하지 않는다.
- 문법 활동은 점수를 내지 않는다. 교사 확인 기준은 §1의 `teacherCheckKo`(미관찰/모범과 함께/단서로/혼자/새 상황)를 그대로 쓴다.

### 12.2 레벨별 문법 초점 표 (제안 · 교사 검수 전)
**Conversation (C1–C6)** — 초점은 §6 각 레벨 표의 "표현·문법" 열 요약이다. 새로 정한 내용이 아니다.

### 12.3 화면·데이터 연결 규칙 (231차 구현 범위 · QA 전용)
1. 홈에 **[📘 문법 (시범)]** 버튼을 [📚 오늘의 학습] 옆에 둔다. 진입은 같은 **과정 → 레벨 → 단원** 선택 화면을 쓰되 의도(intent)만 `grammar`로 다르다.
2. 문법 의도에서는 문법 활동이 있는 Unit이 하나도 없는 레벨을 비활성 '콘텐츠 준비 중'으로 표시한다. 현재 활성은 Conversation 1단계(Unit 1·2)와 2단계(Unit 3)뿐이다. Conversation 3~6단계와 다른 5개 과정의 모든 레벨은 준비 중이다.
3. 문법 의도의 목록은 Unit만 보여 준다(회차 연습 제외). 회차에는 문법 항목이 없기 때문이다. `listCatalog(..., { intent: 'grammar' })`가 Unit만 돌려준다.
4. Unit을 고르면 그 Unit의 문형 활동이 바로 열린다. 활동 화면의 '← 단원'은 Unit 개요로 돌아간다.
5. 데이터 연결은 `src/utils/curriculum/catalog.js`의 `grammarForUnit(unit)`이 `{ titleKo, noticingCount, itemCount }`를 돌려주는 것이 전부다. 기존 Unit 데이터를 읽기만 하고 새 필드·테이블을 만들지 않는다.
6. 저장과 채점이 없다. 선택한 과정·레벨은 세션 상태이며 영구 레벨, 자동 배정, 자동 승급, 점수를 만들지 않는다(§10.6 4번).
7. 모든 레벨 이름에 '(제안)' 표시를 유지한다(§12.0 4번).
- 이 구현은 QA 계정 전용이다(`qaTestStudent`, 오늘의 학습·말하기·쓰기와 같은 게이트). 기능 플래그는 없고, QA 계정이 아닌 학생에게는 버튼도 화면도 보이지 않는다. 학생에게 공개하는 결정은 운영자가 한다.

### 12.4 운영자 확인 항목 (5개 · 짧게 답변)
1. 문법 진입 버튼을 **홈에 따로 둘 것인가, Unit 안에서만 들어가게 할 것인가?** (홈/Unit 안)
2. **회차(ep01~ep10)에도 문법 항목을 만들 것인가?** 지금은 회차에 문법이 없어 문법 진입에서 제외된다. (예/아니오)
3. **문법 문항 형식**을 관찰·선택 외에 쓰기 변형(문장 완성 등)까지 넓혀야 하는가? (예/아니오)
4. **레벨별 문법 범위를 학원이 쓰는 문법 교재 순서와 맞출 것인가?** 맞추려면 교재명과 단원 순서가 필요하다. (맞춤/앱 자체 순서)
5. **Reading 과정과 문법을 분리할 것인가?** 이는 §11.9 ⑩의 "문법은 별도 반인가 각 과정 안인가"와 같은 질문이며, 답에 따라 §12.0 1번 가정이 바뀐다. (별도/안)

### 12.5 (232차, 2026-10-09) 문법 수준 분리·레벨별 문제 세트 (제안 · 교사 검수 전 · QA 전용)
_운영자 요구 원문(수신): "쓰기 말하기 처럼 문법도 초중급 나눠서 문제 풀 수 있게 만들어줘". 리드 해석 = 문법도 말하기·쓰기처럼 자기 수행 수준(`PERFORMANCE_LEVELS`)을 갖고, 학생이 수준별로 나뉜 문법 문제를 푼다. §12.0의 "요구사항 미수신" 가정 중 이 부분은 이 요구로 대체되며, 나머지 가정(점수·저장·DB 없음, '(제안)' 유지)은 그대로다._

**수준별 문법 초점** — `PERFORMANCE_LEVELS`의 `grammarKo`와 현재 문항 현황

| 수준 | grammarKo | 현재 문항(Unit) | 상태 |
|---|---|---|---|
| 입문 | 그림·모양 보고 알맞은 말 고르기 | 0 | 미제작 |
| 기초 | 한 문장 틀에서 빈칸·어순 고르기 | 12 (Unit 1 `c1-borrow-classroom` 6 · Unit 2 `c1-lost-bag-classroom` 6) | 콘텐츠 준비 완료 · 교사 검수 대기 |
| 발전 | 질문과 대답 짝 맞추기·되묻기 고르기 | 6 (Unit 3 `c2-find-together-classroom` 6) | 콘텐츠 준비 완료 · 교사 검수 대기 |
| 확장 | 시제·이유를 이어 알맞은 문장 고르기 | 0 | 미제작 |
| 발표 | 짧은 글에서 틀린 곳 찾아 고치기 | 0 | 미제작 |

**세트 규칙**
1. Unit은 `performance.grammar`로 자기 문법 수준을 선언한다(Unit 1·2 = 기초, Unit 3 = 발전). 값이 있으면 `validateUnit`이 유효한 수준인지 검사한다.
2. 레벨별 세트 = 그 단계(C1·C2…)에 속한 Unit들의 문법 문항 전부(`grammarSetForBlock(units, course, block)`). 지금은 C1 12문항, C2 6문항이며 개수는 데이터에서 센다.
3. 진입은 §12.3의 문법 선택기에서 한다. 단계 버튼에 '· 문법 기초/발전'이 붙고, 단원 목록 맨 위 [📘 이 단계 문법 문제 모아 풀기 (N문항)]이 세트 화면을 연다. 단원 줄에는 문법 수준·문형·관찰·문항 수가 보인다.
