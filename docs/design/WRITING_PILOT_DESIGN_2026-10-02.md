# Writing 파일럿 설계 — "배운 단어로 문장 3개 → 힌트 → 수정 → 선생님 확인"

작성: 2026-10-02. 상태: **설계 문서(코드/DB/외부 호출 0)**. 이 문서가 확정하는 것은 없고,
§13의 운영자 결정이 끝나야 구현 범위가 정해진다. 정확도·비용 수치는 전부 **검증 전 미확정**.

## 1. 목표와 범위

**목표**: 학생이 배운 단어로 짧은 영어 문장 3개를 쓰고, 앱의 짧은 힌트로 스스로 고친 뒤,
애매하거나 반복되는 오류만 선생님이 확인하는 2주 파일럿의 설계.

**이번 범위**: 설계만. 구현·SQL 실행·모델 호출·학생 대상 UI 변경 없음(CLAUDE.md 규칙 8, 12).

**불변 원칙(파일럿에서도 유지)**
- 정답 대필 금지 — 힌트는 "어디를 볼지"만 (`docs/WRITING_COACH.md` §3-1).
- **실제 학생 답안을 외부 AI로 보내지 않는다.** 규칙 기반(비용 0)이 기본값. 외부 모델은
  §9·§13의 전제 조건(보호자/학원 동의 + 익명화 + 운영자 결재)이 **전부** 충족될 때만, 그것도 2주차 선택 사항.
  익명화 = students.id/이름 제거, 문장·목표 단어·학년 단계만 전송. 이름·연락처가 문장에 있으면 전송 전 차단(§6).
- 새 유료 API 전에 무료 대안(규칙 기반)부터 (CLAUDE.md 규칙 7). 새 패키지 추가 없음(규칙 6).
- 학생 식별은 `students.id`(UUID)만 (규칙 4). PIN 관련 컬럼은 클라이언트가 만지지 않음(규칙 11).

**비목표**: 점수/등급 부여, 자유 작문(Free 모드), 보상·게임화 연동, 학부모 노출.

## 2. 기존 구조와 연결

### 2.1 현재 WritingCoach가 하는 일 (사실)
- 한 번에 **문장 1개**. 로컬 순수 모듈만 사용, DB 접근 0, 완료 요약은 `onComplete`로 올리지만 호출부가 버린다
  (`src/components/WritingCoach.jsx:16-21`, `src/App.jsx:839-849`는 `onComplete={() => setScreen('home')}`).
- targetWords = `studentData.round.wordsViewed` **마지막 2개**를 `wordTextById`로 변환 (`src/App.jsx:843-846`).
  "오늘 배정"도 "현재 유닛"도 쓰지 않는다 — 파일럿에서 바뀌어야 할 지점.
- 플래그 `writingCoachEnabled` 기본 OFF (`src/config/features.js:135`).
- `REVEAL_AFTER_ATTEMPTS = 3`, `MAX_FEEDBACK_LINES = 3` (`src/utils/writing/writingSession.js:29,31`).
- 규칙 검사는 14유형 중 5유형만 발화: tense/article/subject_verb_agreement/spelling/punctuation
  (`docs/WRITING_COACH.md` §4-5; `ruleChecks.js:106`). 불확실하면 침묵(오탐 최소화).

### 2.2 "배운 단어" 정의 — 우선순위
| 순위 | 출처 | 근거/조회 | 비고 |
|---|---|---|---|
| 1 | 오늘 반 배정 단어 | `getTodaysAssignmentWordIds(className)` (`wordLibrary.js:4064`), `daily_assignments.word_ids` (`DATABASE.md:65`) | 비어 있으면 "배정 없음" |
| 2 | 학생 현재 유닛 단어 | `students.current_unit_id → units → words.unit_id` (`DATABASE.md:13-50`, v2.1 FK) | 문자열 `unit_name` 매칭 금지 (규칙 3 사고 이력) |
| 3 | 최근 본 단어 | `round.wordsViewed` (현 MVP 방식) | 마지막 수단. 정의가 가장 약함(본 ≠ 배움) |

선정: 위 후보 중 **이미 해당 학생이 `word_status`에서 'unknown'이 아닌 것**을 우선하되,
`word_status` 부재/비어 있으면 필터 없이 진행(폴백). 한 세션 문장 3개 = 단어 3~6개(문장당 1~2개).
파일럿 반은 1순위가 비는 날이 없도록 교사가 배정을 입력(운영 의존) — 비면 2순위로 자동 폴백하고 그 사실을 기록.

### 2.3 ruleChecks 재사용 범위
- **그대로 재사용**: `runRuleChecks`(오류 검출·힌트), `errorTaxonomy` 14코드, `submitAttempt`의 자가 수정 집계.
- **확장 필요(설계 시 놓치기 쉬움)**: `usedTargetWords`는 whole-word 매칭이라 `park`→`parks`,
  `go`→`went`를 "미사용"으로 본다 → §5의 형태 변화 허용 검사 필요.
- **한계 명시**: 규칙이 침묵한다고 문장이 맞는 것이 아니다(14유형 중 9유형 미검사,
  `vocabulary_choice`/`unnatural_expression`/`word_order` 등은 의미·자연스러움 영역). 그래서 규칙 "오류 없음"을
  곧바로 "통과"로 쓰지 않는다 — §4.
- `writingReview*` 플래그(`features.js:155-192`)는 **쓰기시험(spelling) 오답 검수 큐**용이지 문장 작문용이 아니다
  (`SpellingReviewQueuePanel.jsx`, `grade-writing-answers` Edge Function). 이름이 비슷해도 재사용 대상은
  "교사 승인/반려 UI 패턴"과 "비용 상한 게이트(`evaluateCostGate`)" 정도이고 데이터 경로는 별개다.

## 3. 학습 수준별 문제와 예시

공통: 문장 3개, 목표 단어는 문장당 1~2개, 학생은 한 문장씩 쓴다. 단계는 `classes`/교사 지정 값
(학년 자동 추정은 하지 않음 — `classes` 컬럼에 학년 정보가 확인되지 않음, **확인 필요**).

| 단계 | 문장 길이 | 과제 형태 | 예시 1 | 예시 2 |
|---|---|---|---|---|
| 초등 저(3~4학년) | 3~6단어 | 단어 1개, 쉬운 틀 제공("I like ___.") | 목표 `apple` → "I like apples." | 목표 `big` → "The dog is big." |
| 초등 고(5~6학년) | 5~9단어 | 단어 1~2개, 틀 없음 | 목표 `library`,`read` → "I read books in the library." | 목표 `yesterday`,`play` → "I played soccer yesterday." |
| 중등 1 | 6~12단어 | 단어 1~2개 + 시간/장소 조건 | 목표 `usually`,`walk` → "I usually walk to school with my friend." | 목표 `because`,`tired` → "I am tired because I studied late." |
| 중등 2 | 8~15단어 | 접속/비교 구조 요구 | 목표 `taller` → "My brother is taller than me." | 목표 `if`,`rain` → "If it rains, we will stay home." |
| 중등 3 | 10~20단어 | 교과서 문법 포인트 1개 포함 | 목표 `finish`,`before` → "I finished my homework before dinner started." | 목표 `want`,`visit` → "I want to visit Jeju with my family." |

주의: 위 예시는 **설계용 샘플**이며 실제 교재 단어(`words.word`)로 교체해야 한다. 단어가 구(phrase)나
뜻 위주 항목일 수 있어(`DATABASE.md:50-57`에서 컬럼 구성이 "역추적, 100% 일치 미확인") 파일럿 반 단어 20개를
교사가 훑어 "문장화 가능 단어"만 남기는 사전 단계가 필요하다.

## 4. 채점 기준 — 3축, 3상태

**3축**
1. **목표 단어 사용**: 목표 단어(또는 허용 형태, §5)가 문장에 있는가. 결정론적, 규칙으로 판정 가능.
2. **의미(문맥 적합)**: 단어가 문맥에 맞게 쓰였는가("I eat a library."). 규칙으로는 **판정 불가** →
   파일럿 1주차는 교사 확인, 2주차에 모델 판정(선택)을 비교 측정.
3. **문법**: 기존 `errorTaxonomy` 코드로 분류. 규칙은 5유형만 검출, 나머지는 교사/모델.

**3상태(점수 아님)**
| 상태 | 의미 | 학생에게 보이는 것 |
|---|---|---|
| 통과 | 축1 충족 + 규칙 오류 0 + 아래 "불확실 신호" 없음 | "완성!" (현 완료 화면 재사용) |
| 수정 필요 | 규칙이 확실히 잡은 오류가 있음 | 짧은 힌트 최대 3줄 |
| 선생님 확인 | 자동으로 확신 못 함(§6 기준) | "선생님이 볼게요" |

**왜 점수가 아닌가**: (1) 규칙 검사 커버리지가 5/14라 숫자가 정밀해 보일 뿐 근거가 없다.
(2) 초등 학생에게 점수는 자가 수정 동기를 "점수 올리기"로 바꿀 수 있다 — 이 효과 자체는 본 설계가 검증하지 않았고
(**미확인**), 현 코치의 철학(자가 수정 비율이 KPI, `WRITING_COACH.md` §1)과 상충한다.
(3) 3상태는 교사 업무(무엇을 봐야 하나)와 1:1로 대응해 측정(§11)이 단순해진다.

**"통과"의 정직한 이름**: 규칙 전용 모드에서 통과는 "규칙 범위 내 오류 없음"일 뿐이다. 교사 대시보드에는
`통과(규칙)`로 표기하고, 파일럿 중 통과 건의 **무작위 20%를 교사가 사후 표본 확인**해 오답 통과율(§11)을 잰다.

## 5. 여러 정답 허용 — 제약 충족 검사

기준 정답 목록을 두지 않는다(정답 문장이 무한). 대신:
`제약 검사(결정론) → 규칙 검사(기존) → [선택] 모델 판정` 순서, 앞 단계에서 확정되면 다음은 호출하지 않음
(`WRITING_COACH.md` §7의 "규칙 먼저, 미해결만 AI"와 동일).

**제약 검사**: 목표 단어(허용 형태 포함) ≥ 1개 포함 / 단어 수가 단계별 범위 내 / 금지 패턴(§6) 없음 /
예문·교재 문장 통째 복사 아님(교재 예문과 정규화 후 완전 일치 시 "선생님 확인").

| 항목 | 허용 | 허용하지 않음(→ 선생님 확인 또는 수정 필요) | 구현 근거 |
|---|---|---|---|
| 형태 변화(규칙) | -s/-es, -ed, -ing, -er/-est (`park→parks`, `play→played`) | 어간이 불명확한 변형 | 접미 규칙(신규, 소규모) |
| 형태 변화(불규칙) | `go→went`, `have→has` 등 **기존 사전에 있는 것** | 사전에 없는 불규칙 | `PAST_TENSE_MAP`/`THIRD_PERSON_MAP` (`ruleChecks.js:29,40`) 재사용 |
| 철자 | 편집거리 1은 "수정 필요(spelling)" 힌트, 사용으로는 미인정 | — | 규칙 spelling 유형 |
| 동의어 | 목표 단어를 쓰지 않았으면 **미사용**(과제 조건 불충족). 문장 자체는 오류 아님 | — | 목표 단어 연습이 과제 목적 |
| 어순 | 같은 뜻의 다른 어순은 규칙이 건드리지 않음(침묵). 명백한 오류는 모델/교사 | — | 규칙은 어순 미검사 |
| 대소문자 | 문장 첫 글자·`I`만 검사 | 고유명사 대소문자(오탐 위험) | 기존 규칙 범위 |
| 금지 | — | 한글 포함, 영문자 비율 낮음, 반복 단어 나열 | 제약 검사 |

## 6. 선생님 전달 기준과 포맷

**전달(→ `teacher_check`) 조건 — 하나라도 해당**
1. **확신 낮음**: 제약 통과 + 규칙 오류 0이지만 *불확실 신호* 보유 — 문장 길이가 단계 하한 미만/상한 초과,
   목표 단어가 허용 형태로만 매칭(정확 일치 아님), 규칙 사전 밖 동사 다수(미지 토큰 비율 높음), 교재 예문과 완전 일치.
   (현 `runRuleChecks`는 confidence 필드가 없다 — 파일럿에서 위 신호로 **파생**하며, 규칙 모듈 변경 여부는 §13.)
2. **같은 오류 유형 2회 반복**: 같은 세션 내 같은 `type`이 연속 2번 제출에서 남음, 또는 세션 간 같은 유형 반복.
3. **힌트 2회 후에도 미수정**: 같은 오류가 힌트 2번 뒤에도 남음(= 3번째 제출에서 에스컬레이션).
4. **금칙어/개인정보 패턴**: 이메일·전화번호 형태, 욕설 목록, 학생이 자기/타인 실명을 쓴 것으로 보이는 패턴.
   → 서버 저장 전에 **마스킹**하고 교사 확인으로 보낸다. 외부 모델 전송 대상에서 항상 제외.
5. **모델 판정 사용 시**(2주차 선택): 모델 판정과 규칙 판정이 충돌하면 항상 교사에게.

**전달 포맷(교사 화면/저장 공통)**
| 필드 | 내용 |
|---|---|
| student_id | `students.id` UUID (화면에는 admin이 이미 아는 `getStudents()`로 이름 매핑 표시, 저장은 UUID만) |
| target_words | 이번 문장의 목표 단어 |
| sentence | 최신 제출 문장(필요 시 마스킹 적용본) + 첫 제출 문장 |
| error_types | taxonomy 코드 배열(규칙/모델 출처 구분) |
| hint_history | [{attempt_no, hints[], text}] — 몇 번째에 어떤 힌트를 줬나 |
| reason | 위 조건 1~5 중 어느 것인지 |

## 7. 재연습 + Teacher Check 흐름

**상태 머신(문장 단위, 세션=문장 3개)**
```
draft ──제출──▶ [자동 판정]
  ├ 통과 ─────────────────────────────▶ passed (규칙 통과, 표본 확인 대상)
  ├ 수정 필요 ─▶ hinted ──제출──▶ revised ──▶ [자동 판정] 반복(힌트 최대 2회)
  └ 전달 조건 ─────────────────────────▶ teacher_check ──교사──▶ passed | retry
retry: 교사 코멘트(선택) + 같은 문장 재작성 허용 1회, 이후엔 다음 날 재연습 큐
```
- 기존 `startSession/submitAttempt`가 draft→hinted→revised→completed를 이미 구현 — 추가분은 `teacher_check`/`retry`
  상태와 에스컬레이션 판정뿐. 단 현 코드는 **3번째 시도에서 정답 공개**가 열린다(`writingSession.js:131`).
  파일럿에서는 에스컬레이션(3번째 제출)과 겹치므로 **공개를 끄고 교사가 설명**하는 쪽을 권장(§13 결정).
  이유: 공개 후 수정은 자가 수정으로 안 세는데(`WRITING_COACH.md` §3-6), 교사 확인 대상 문장에 정답이 이미 보이면 측정이 오염.

**재연습 큐**
- 유사점: 학생별 목록, 다음 학습 때 자동 노출, 같은 학생 UUID 기준.
  `spellingReviewQueue`는 `useStudent` 레코드의 단어 id 배열이고 기기 간 합집합으로 병합된다
  (`src/hooks/useStudent.js:439,455`).
- 차이: 쓰기 재연습은 **단어가 아니라 (오류 유형, 문장)** 단위이고, 해소 판단에 **교사 결정이 들어가므로
  서버 상태가 필요**하다 → `progress_data`(로컬 우선 백업)에 얹지 않고 §8의 테이블에서 파생.
  (`student_progress.progress_data`는 클라이언트가 직접 쓰는 값이라 교사 확정 상태의 진실 원천으로 부적합.)
- 큐 규모 상한: 학생당 미해소 3건. 초과분은 가장 오래된 것부터 교사 화면에서만 처리(학생에게 쌓이는 숙제로 보이지 않게).

**교사 화면 최소 요구** (신규 관리자 패널 1개, 기존 `AdminScreen` + `components/admin/*` 패턴; 플래그는 신규 1개 권장)
- 목록: 반/날짜 필터, 상태가 `teacher_check`인 건만, 사유(§6) 배지.
- 한 건: 학생 이름(UUID 매핑), 첫 문장→최종 문장, 힌트 이력, 오류 유형, [통과][재작성][메모] 버튼 3개. 일괄 처리 없음(파일럿은 건수가 적음).
- 소요 시간 측정용: 열람~결정 타임스탬프(§11).
- 재사용: 승인/반려 UI 패턴(`SpellingReviewQueuePanel.jsx`). `writingReviewAutoPilot` 류의 **자동 인정은 이 파일럿에 도입하지 않음**.

유형·횟수·상태)은 학기 말까지. 학생 삭제 시 CASCADE. 삭제는 운영자 수동(자동 삭제 크론은 이번 범위 밖).

권장: 학생 쓰기는 insert 중심, **교사 열람·결정은 service_role 경유(Edge Function)**. 단 anon 키로는 DB가
"이 요청이 이 학생"임을 증명하지 못하므로(앱의 `setSessionToken` 검증 경로가 이 테이블에 적용되는지 **확인 필요**)
"자기 행만 select" RLS는 현 구조에선 강제 불가 — 한계로 인정하고 문장에 개인정보 마스킹(§6-4)으로 보완.
`students` 컬럼 추가는 없으므로 규칙 10 GRANT 문제는 해당 없음. PIN 컬럼 접근 0 (규칙 11).

**테이블 부재 시 클라이언트 동작(결정 제안)**: 기능 비활성이 아니라 **로컬 루프는 계속 동작**
(현 MVP와 동일, 규칙 9) + `teacher_check` 상태 진입 대신 "오늘은 여기까지" 종료 + 저장 안 됨.
로컬 저장 후 업로드 큐는 만들지 않는다 — 공용 기기에서 학생 문장이 남고, 중복 업로드/PII 위험이 커서(YAGNI).
부재 감지는 기존 `isMissingTableError` 관례(42P01/PGRST205). 파일럿은 **SQL 실행 후에만 시작**하므로 이 폴백은 안전망.

## 9. 모델 후보·호출량·비용·검증

**전제**: 외부 모델은 동의·익명화·운영자 결재 전 사용 금지(§1). 아래는 후보 비교이며 **정확도·비용은 검증 전 미확정**.

| 후보 | 비용 | 장점 | 미확정/위험 |
|---|---|---|---|
| A. 규칙 기반만 | 0원 | 결정론, 외부 전송 0, 지금 있음 | 의미·자연스러움 미검사 — 선생님 확인 비율이 높아질 수 있음(측정 대상) |
| B. Claude Haiku 4.5 | 미확정(공식 단가 확인 후 계산) | 저가·빠름 후보 | 한국 초등 EFL 문장에서의 오판율 **미측정** |
| C. Claude Sonnet 5.5 | 미확정 | 의미 판정 정확도가 높을 가능성 | 비용·정확도 **미측정**. 문장 단위엔 과할 수 있음 |
| D. Gemini 등 타사 | 미확정 | 무료 티어 존재 가능성(**확인 필요**) | 무료 티어는 입력이 학습에 쓰일 수 있는 약관이 흔함(**확인 필요**) → 학생 답안엔 부적합할 수 있음 |
| (참고) 현 Edge Function | — | `grade-writing-answers`가 이미 provider 추상화 보유 | 기본값이 `gpt-5-nano`/`openai`(`pipeline.js:203-204`) — 쓰기시험 오답 검수용이지 문장 첨삭용 아님 |

**호출량 추정식(모델 사용 시에만)**
`호출 수 ≈ 학생 수 × 문장 3 × 세션 수 × 평균 제출 횟수 × 모델 호출 비율`
예시(가정값, 근거 아님): 12명 × 3 × 6세션(2주 중 주 3회) × 1.6 ≈ 346회, 모델 호출 비율 = 규칙이 확정하지 못한 건만(0.3~1.0, **미측정**)
→ 약 100~350회. 입력은 compact state(원문+현재문장+남은 오류 코드+목표 단어)라 시도 횟수와 무관하게 토큰이 상수에 가깝다
(`WRITING_COACH.md` §6). 단가는 확정 후 `토큰 × 단가`로 계산 — 이 문서는 금액을 적지 않는다.

**검증 방법(모델 도입 전 필수)**
1. 교사 라벨 **골드셋 200문장**: 1주차 실제 제출에서 층화 추출(수준 단계·오류 유형·통과/비통과 균형), 교사 2인 독립 라벨 가능하면 일치율(κ)도 기록.
2. 후보별로 동일 골드셋 판정 → 지표: **교사-모델 일치율**, **오답 통과율**(교사가 '수정 필요'인데 '통과'로 판정한 비율 — 최우선), 과잉 경고율.
3. 채택 기준 임계값(예: 오답 통과율 상한)은 **교사·운영자가 사전 합의**해 기록한 뒤 측정(결과 보고 나서 기준 조정 금지).
4. 200문장 확보 실패 시(문장 부족) 모델 단계는 보류 — 규칙 전용으로 종료.

**호스팅**: Vercel Hobby 서버리스 함수 12개 한도로 새 API route 불가(`WRITING_COACH.md` §7, handoff 88차 `handoff.md:9062` 부근).
옵션: **A) Supabase Edge Function**(`supabase/functions/`에 `grade-writing-answers` 등 선례 3개 — 한도 무관, 유력),
B) 기존 함수 통합(회귀 위험), C) Vercel Pro(유료·최후순위). 어느 쪽이든 API 키는 서버 환경변수에만.
이번 파일럿 **1주차는 호스팅 결정이 필요 없다**(규칙 전용 + 교사 확인; 저장도 Supabase 직접 쓰기).

## 10. 2주 파일럿 계획

범위: **한 반 · 한 유닛 · 학생 8~15명**(반/유닛 선정은 §13). 세션 15분, 주 3회, 문장 3개.

| 기간 | 내용 | 산출 |
|---|---|---|
| 준비(D-5~D-1) | 운영자가 SQL 실행·검증, 교사가 단어 20개 문장화 가능 여부 확인(§3), 동의 절차 완료, 플래그 파일럿 반 한정 | 준비 체크리스트 |
| 1주차 | **규칙 + 교사 확인만**(외부 모델 0). 모든 `teacher_check`를 교사가 처리, 통과(규칙) 20% 표본 확인, 교사 소요시간 기록 | 골드셋 후보 문장(200 목표) |
| 주 중 점검(W1 금) | 지표 1차 확인 → 계속/수정/중단 판단 | 점검 메모 |
| 2주차 | (조건부) 동의·결재가 있고 골드셋 검증이 임계값을 넘은 경우에만 모델 판정 **그림자 모드**(결과를 학생에게 보이지 않고 교사 판정과 비교). 아니면 규칙 전용 반복 + 재연습 큐 검증 | 비교 보고서 |
| 종료 | 지표 요약, 보관 기간에 따른 원문 삭제, 확장/중단 결정 | 결과 요약 1장 |

**역할**: 교사 — 단어 선정, `teacher_check` 처리, 라벨링, 표본 확인. 운영자 — SQL 실행, 플래그/반 선정, 동의·결재, 중단 결정.
개발 — 상태 머신 확장, 교사 패널, 로깅(별도 구현 계획 필요; 이 문서 범위 밖), 장애 대응.

**중단 기준(하나라도 해당 시 즉시 플래그 OFF)**
- 학생 문장에서 개인정보가 마스킹을 통과해 저장된 사례 1건 이상.
- 규칙이 틀린 힌트(오탐)로 학생이 맞는 문장을 고치게 만든 사례를 교사가 3건 이상 확인.
- 교사 소요 시간이 합의 한도(예: 학생당 일 3분)를 2일 연속 초과.
- 기존 학습/로그인/동기화 플로우 회귀 1건(규칙 1).
- 학생이 힌트 대신 정답 공개를 기대하며 이탈하는 등 사용 거부 징후가 반 교사 판단으로 지속.

## 11. 측정 방법

| 지표 | 정의 | 수집 |
|---|---|---|
| 교사-AI(규칙/모델) 판정 일치율 | 골드셋·표본에서 자동 판정 = 교사 판정 비율 | 교사 라벨 + 자동 판정 대조(스크립트, 파일럿 후 분석) |
| 오답 통과율 | 교사 '수정 필요' 중 자동 '통과'로 나간 비율(**최우선 안전 지표**) | 통과(규칙) 20% 표본 확인 |
| 힌트 후 수정률 | 힌트를 받은 오류 중 다음 제출에서 해소된 비율 = `self_corrected_count / 오류 수` | `writing_submissions` 컬럼 그대로 (`WRITING_COACH.md` §9 KPI) |
| 교사 소요 시간 | 분/학생·일 | 패널 열람~결정 타임스탬프(주), 부족하면 교사 수동 기록(보조) |
| 학생별 비용(원) | 모델 사용 시 `(토큰 × 단가) ÷ 학생 수`. 규칙 전용이면 0 | 호출 로그(Edge Function) — 모델 미사용 시 해당 없음 |

수집: 정식 지표는 위 테이블이 원천(교사 결정 포함). 기존 익명 이벤트 `trackEvent`(`src/utils/productEvents.js:29`,
anon_id = sha256 해시, 플래그/테이블 부재 시 no-op)는 **참여율(세션 시작/완료)** 보조용으로만 쓰는 것을 제안 —
교사 판정·문장은 이벤트에 넣지 않는다. 주의: 우리 파일럿은 표본이 작아(학생 ~10명) 비율 지표의 신뢰구간이 넓다 —
결과는 "방향성"으로만 읽고, 통계적 유의성을 주장하지 않는다. 사용량 지표로 기능 성패를 단정하지 않는다
(방학/시험기 등 맥락 확인 — 운영 메모리의 사용량 해석 원칙).

**논문이 직접 뒷받침하지 않는 것(전부 "미확인")**
- 초등 EFL 아동에게 앱 힌트가 쓰기 실력을 올린다.
- 자동 힌트 후 **학생 스스로 수정**하는 방식이 교사 직접 교정보다 낫다(자가 수정 효과는 별도 문헌이 필요하고 여기선 확인하지 않음).
- 점수 없는 3상태 피드백이 동기에 유리하다.
- 3개 문장·15분 세션 길이가 적절하다(파일럿에서 관찰할 가설).
