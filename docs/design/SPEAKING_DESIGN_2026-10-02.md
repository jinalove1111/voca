## 2. 단계 구분

| 단계 | 입력 | 출력 | 주요 실패 모드 | 오프라인 |
|---|---|---|---|---|
| ① 녹음 | 마이크 스트림 | 오디오 Blob(webm 등), 길이, 무음 여부 | 권한 거부, 인앱 브라우저, 기기 점유, iOS Safari MediaRecorder 코덱 차이 **(확인 필요)**, 배경 소음으로 무음 오판(임계 0.02 고정) | 가능(현재 동작) |
| ② 음성 인식(ASR) | Blob 또는 실시간 스트림 | 텍스트 + confidence | 아동 음성 인식률 저하, 짧은 단어 오인식, 네트워크 실패, 지연 | 브라우저 Web Speech는 일부 브라우저가 서버 의존 **(확인 필요)**; 서버 ASR은 불가 |
| ③ 내용·목표 표현·문법 평가(텍스트) | ASR 텍스트 + 목표 단어/표현 | "목표 표현 포함 여부", 문장 형태 점검 | ASR 오류를 학생 오류로 오판, 사투리/억양 변형, 동음이의 | 규칙 기반(문자열 정규화·편집거리)은 가능, 모델 기반은 불가 |
| ④ 발음 평가(음향) | 오디오 자체 + 기준 텍스트 | 음소/단어 단위 점수 | 아동 규준 부재, 외부 전송 동의 필요, 비용 | 불가(외부 API) |
| ⑤ 학생 재연습 | 피드백, 원어민 TTS/mp3 | 재녹음 시도 | 같은 피드백 반복 → 좌절, 보상 farming | 가능 |
| ⑥ 선생님 확인 | 큐 항목(+선택적 오디오) | 확인/코멘트 | 교사 부담 폭증, 오디오 보관 문제 | 불가(서버 기록 필요) |

**원칙: 텍스트만으로 발음 점수를 만들지 않는다.** ③의 ASR 텍스트 일치는 "그 단어로 알아들었다"는 증거일 뿐 발음 정확도가 아니다. 발음 점수(④)는 오디오 음향을 입력으로 받는 평가기에서만 나오며, 그런 평가기가 없으면 발음 점수는 만들지 않고 "점수 없음" 상태로 둔다.

## 3. ASR 오류 ≠ 학생 영어 오류 — 분리 경로

아동 음성의 ASR 정확도가 성인 대비 낮다는 것은 알려진 사실이다(연령이 낮을수록, 비원어민 억양일수록 악화; 근거 11장). 정확도 수치는 본 앱 데이터가 없어 **미확정**.

기본값 = **점수 미부여 + 연습 인정**. 평가 결과가 불확실하면 학생에게 "틀렸다"를 말하지 않는다.

```
녹음 → [품질 게이트] → ASR → [신뢰도 게이트] → 텍스트 비교 → 표시
```

| 게이트 | 조건 (임계값은 파일럿에서 보정, 초기 수치 확정 금지) | 결과 |
|---|---|---|
| 품질 | 길이 < 최소, 무음 비율 과다, 클리핑 | "소리가 잘 안 들렸어요. 다시 해볼까요?" 재녹음 제안, 시도 횟수 불산입 |
| 신뢰도 낮음 | confidence < T_low 또는 ASR가 빈 문자열 | **"AI가 잘 못 들었어요"** 문구, 학생 오류로 기록하지 않음, 재녹음 1회 제안 |
| 불일치 + 신뢰도 높음 | confidence ≥ T_high 인데 목표와 다름 | "다시 한 번 들어보고 따라 해봐요" 중립 문구(틀림 표시 금지), 재연습 |
| 반복 불확실 | 같은 단어에서 연속 N회 불확실/불일치 | **교사 확인 큐**로 전송(7장), 학생에게는 "선생님이 들어봐 주실 거예요" |
| 일치 + 신뢰도 높음 | 목표 포함 | 긍정 피드백. 단, "정확한 발음"이 아니라 "알아들었어요" 의미의 문구 |

기록 시 `asr_status`를 **학생 판정과 분리**한다: `asr_status`(ok/low_conf/empty/error)와 `match`(match/mismatch/unknown)는 별도 컬럼. `asr_status != ok` 이면 `match = unknown`이어야 하며 어떤 통계에도 "학생 오류"로 집계하지 않는다. confidence를 주지 않는 ASR(Web Speech 일부 구현 포함 **(확인 필요)**)이면 신뢰도 게이트를 못 쓰므로 불일치 시 항상 `unknown` 취급 + 교사 큐 쪽으로 보수적으로 처리한다.

## 6. 최소 기록 — speaking_attempts 초안 (SQL 아님)

## 7. 교사 확인 흐름

**큐 진입 조건** (이 중 하나)
1. 같은 단어에서 연속 N회 `low_conf`/`mismatch` (N은 파일럿에서 결정)
2. 학생이 "선생님께 들려주기"를 직접 선택(동의 있는 학생만, 오디오 저장안일 때)
3. 교사가 특정 학생/단어를 지정

**교사 화면 최소 항목**: 학생(이름 표시는 UI용, 키는 `students.id`), 단어/목표 표현, 시도 횟수, `asr_status`, `match`, (저장안일 때만) 오디오 재생, 판정 버튼(좋아요 / 다시 해보기 / 직접 지도 필요), 짧은 코멘트. 발음 점수는 있을 때만 표시하고 없으면 "점수 없음"으로 명시.

**학생 재연습 루프**: 교사 "다시 해보기" → 학생 홈/단어 화면에 해당 단어 재연습 표시 → 원어민 듣기 → 재녹음 → 큐 조건 재평가. 재연습 보상은 기존 dedupKey 하루 1회 규칙 그대로(farming 방지, 보상 경로 불변).

**부담 통제**: 교사 하루 확인 건수 상한/반별 묶음 표시를 파일럿에서 측정(수치 미정). 큐가 과적되면 임계값을 완화하지 말고 큐 진입 조건을 줄인다.

## 9. 파일럿 제안 (설계만)

- 범위: 한 반, 2주, 동의 받은 학생만. 기본은 서버 오디오 저장 없음.
- 구현 최소: 품질 게이트(b) + 텍스트 ASR 1종 + `speaking_attempts` 기록 + 교사 큐 화면 최소판. 발음 점수(c)는 포함하지 않는다.
- 측정 항목(모두 집계 지표; 수치 목표는 사전 확정하지 않음):
  - ASR 거부율: `low_conf` + `empty` + `error` / 전체 시도
  - 교사 확인 비율: `queued` / 전체 시도, 교사 1인당 일 확인 건수·소요 시간
  - 재녹음 횟수: 단어당 시도 분포, 품질 게이트 재시도 비율
  - 교사 판정과 ASR `match`의 일치/불일치(샘플 대조, ASR 신뢰도 보정용)
  - 학생 반응: **관찰 기록으로만**(교사 메모). 사용량 수치로 효과·성패를 추론하지 않는다(메모리 지침: 낮은 사용량은 방학·파일럿 등 맥락부터 확인).
- 종료 판단: ASR 거부율이 높고 교사 부담이 과하면 서버 ASR 도입을 중단하고 (a)/(b) 유지 — 이는 정상적인 결과로 간주.
