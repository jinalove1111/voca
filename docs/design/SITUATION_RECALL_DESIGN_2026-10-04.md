## 1. 목표·범위

**목표**: 초등 초급 학습자가 "이 상황에서는 이 표현"이라는 짝을 그림으로 이해하고, 문장을 가린 채 그림만 보고 떠올려 말해 보고, 다른 상황에 같은 표현을 적용해 보고, 다음 학습 때 다시 만나게 한다.

**흐름(운영자 요구)**: 상황 그림 → 음성+문장 → 문장 숨기고 그림만 보고 말하기 → 다른 상황에 같은 표현 적용 → 다음 학습에서 복습.

| 구분 | 이번 구현 범위 | 후속(이번 범위 아님) |
|---|---|---|
| 콘텐츠 | 표현 5개 × 상황 2개 = 장면 10개(임시 그림, 기존 에셋 합성) | 최종 그림 10장 납품 후 교체, 표현 추가 |
| 화면 | 보기 → 회상 → 전이 → 요약, 복습 진입, Speaking 화면 상단 버튼 | 교사 대시보드 연동 |
| 음성 | `speak(text)`(`src/utils/speech.js`) 재생, 자체 `getUserMedia` 스트림 녹음, Blob은 메모리에만 | ASR/발음 평가(Speaking 설계 §4 단계 권고 따름) |
| 저장 | 기기 로컬 `localStorage`, 키에 `students.id` UUID 포함. DB/서버 0, 오디오 저장 0 | 서버 동기화(기기 간 이동, 교사 열람)는 별도 결정 |
| 보상 | 없음(별/포인트 연동 안 함. farming·"숙달" 오해 방지) | 필요 시 별도 설계 |

기존 기능 보존: `SpeakingPractice.jsx`, `speakingSession.js`, `speech.js`는 수정하지 않는다(재사용만). 신규 컴포넌트/유틸을 별도 파일로 추가하고 Speaking 화면에는 진입 버튼 1개만 더한다. 학생 식별에 이름 문자열을 쓰지 않는다.

## 2. 표현 5개 선정

선정 기준: 2~6단어, 초등 초급이 일상에서 실제 쓰는 고빈도 표현, **상황이 표현을 결정**(그림만 보고 "언제 쓰는지" 판단 가능), 서로 상황이 겹치지 않음. 제안 5개를 그대로 채택한다(대체 불필요: 모두 2~5단어, 상황 단서가 뚜렷).

| id | EN | KO(아이 말투) | 단어 수 |
|---|---|---|---|
| `hello` | Hello! Nice to meet you. | 안녕! 만나서 반가워. | 5 |
| `help` | Can you help me, please? | 나 좀 도와줄래? | 5 |
| `sorry` | I'm sorry. | 미안해. | 2 |
| `thanks` | Thank you so much! | 정말 고마워! | 4 |
| `play` | Let's play together! | 우리 같이 놀자! | 3 |

### 상황 A(주 그림) / 상황 B(전이 그림)

| id | 상황 A | 상황 B | 그림이 용법을 설명하는 이유(단서) |
|---|---|---|---|
| `hello` | 학교 앞에서 처음 보는 친구와 마주 서서 손 흔드는 장면 | 다리 위에서 처음 보는 동네 친구를 만나 손 흔드는 장면 | "처음 보는 상대"(낯선 얼굴 + 서로 마주봄 + 손 흔들기). 같은 표현이 장소가 달라도 "처음 만남"이면 쓰임을 보여줌 |
| `help` | 서점에서 높은 곳의 책을 못 꺼내 곤란해하고 옆에 도와줄 사람이 있는 장면 | 길 표지판 앞에서 길을 몰라 곤란해하고 지나가는 사람이 있는 장면 | "혼자 못 함 + 도와줄 사람이 곁에 있음". 곤란한 표정 + 물음표 말풍선 |
| `sorry` | 내가 화단 화분을 넘어뜨려 꽃이 쏟아졌고 친구가 속상해 보는 장면 | 카페에서 내가 컵을 쏟아 친구 옷/바닥이 젖은 장면 | "내 실수 + 피해 입은 상대". 엎질러진 것이 원인 단서, 상대의 표정이 결과 단서 |
| `thanks` | 상대가 내게 선물 상자를 건네주는 장면 | 카페에서 상대가 내 앞에 간식을 놓아주는 장면 | "받는 사람이 나". 건네는 손 + 선물/음식 + 웃는 표정 |
| `play` | 공원에서 혼자 공을 든 친구가 있고 내가 다가가는 장면 | 분수 옆에서 심심해 보이는 친구에게 놀이를 청하는 장면 | "함께 할 상대 + 놀 거리"(공/놀이터). 청하는 쪽의 손짓 |

곤란/실수/감사는 **표정만으로 구분되지 않도록** 반드시 원인 소품(엎지른 컵, 선물, 높은 선반)을 함께 그린다(색 의존·표정 의존 금지).

## 5. 화면·흐름

한 화면에 **그림 1장 + 핵심 표현 1개**. 목록 화면 없음. 진입: Speaking 화면 상단 버튼 `🖼️ 상황 보고 말하기`, 종료 시 Speaking 화면으로 복귀.

```
[진입] → (복습 대상 있으면) 복습 모드: 회상부터 → 표현별 루프 → [요약]
        (없으면) 표현1: 보기 → 회상(A) → 전이(B) → 표현2 …
```

### 상태

| 상태 | 화면 구성 | 동작 |
|---|---|---|
| intro(보기) | 그림 A, EN 크게 + KO, `🔊 듣기`, 선택 `🎤 따라 말하기`, `다음` | 듣기는 `speak(en)`. 따라 말하기는 선택(안 해도 진행) |
| recall(그림만) | 그림 A만. EN/KO 숨김. 하단 `💡 힌트` 구역 | 아래 힌트/말하기/자기 보고 |
| transfer | 그림 B(다른 상황), 동일 규칙으로 recall과 같은 화면 | 안내 문구 "다른 곳에서도 같은 말을 쓸 수 있어요" |
| next | 다음 표현으로 | 마지막이면 summary |
| summary | "오늘 연습한 표현" 목록 + 자기 보고 아이콘, `돌아가기` | 점수/별/완료 표시 없음 |

### recall/transfer 화면 규칙

- 힌트(순차, 되돌리기 없음, 각 클릭은 기록): `💡 힌트 1` 첫 단어 + 나머지 밑줄(예: `Can ___ ___ ___`) → `힌트 2` EN 전체 → `힌트 3` KO 뜻. 힌트는 서로 다른 시각 영역에 두어 말하기 버튼과 섞이지 않게 한다.
- `🎤 말하기` / `▶ 들어보기`는 Speaking 화면 로직 재사용(별도 스트림 `getUserMedia({audio:true})`, MediaRecorder, `pickMimeType`/`mapMediaError`, Blob은 메모리, 해제 시 `URL.revokeObjectURL`, 언마운트/뒤로가기에서 트랙 stop). `speakingReducer` 상태기계를 재사용하거나 동일 패턴으로 구성(구현 시 선택).
- 말하기 후 자기 보고 2버튼: `말할 수 있었어요` / `아직 어려워요`. **자기 보고는 학생의 주관 기록일 뿐** 완료/숙달/성공으로 표시하지 않는다. 텍스트·아이콘 모두 "기억함/마스터" 표현 금지(예: ✅ 대신 🙂/🌱 중립 아이콘 + 텍스트 라벨).
- 버튼 클릭 자체는 어떤 상태에서도 "기억/숙달"으로 판정하지 않는다. 녹음이 있어도 판정하지 않는다(Speaking 설계: 참여일 뿐).
- 자기 보고 전에는 `다음`이 비활성이어야 하는가? 아니다. 안 눌러도 넘어갈 수 있게 하여 강요된 보고를 막는다(미보고는 "미기록"으로 저장).

### 모바일 규칙

- 그림 `min-h-[40vh]`, `w-full max-w-lg`, `object-contain`. 글자·그림이 화면 폭에 맞춰 줄어들지 않도록 EN은 `text-2xl` 이상, KO는 `text-base` 이상, 줄바꿈은 허용하되 폰트 축소 금지.
- 버튼 높이 ≥ 44px, 간격 ≥ 8px. 스크롤 필요 시 그림은 위에 고정, 버튼은 아래로 흐름(그림이 먼저 보임).
- 한 화면 한 표현. 목록/표 금지(요약 제외).

## 6. 다음 학습에서 복습

기기 로컬 레코드(키: `situationRecall:v1:<students.id UUID>`):

```
{ studentId, expressionId, lastPracticedDate, selfReports[], hintUsed[] }
```

- `lastPracticedDate`: 로컬 날짜 `YYYY-MM-DD`(기기 시간 기준).
- `selfReports[]`: `{date, stage:'recall'|'transfer', value:'ok'|'hard'|null}` 최근 N=10개만 보관.
- `hintUsed[]`: `{date, stage, maxHint:0|1|2|3}` 최근 N=10개.
- 사용자 전환 시 다른 UUID 키를 읽으므로 섞이지 않는다. 이름 키 금지.

**복습 규칙(단순 휴리스틱, 적응 모델 아님)**

1. 진입 시 이전 날짜에 연습한 표현 중 "도래한" 것을 먼저 `복습`으로 배치(회상 단계부터, 그림 A → B 순).
2. 도래 조건: 마지막 연습일로부터 ≥ 1일. 단 마지막 두 번의 recall 자기 보고가 모두 `ok`이면 ≥ 3일.
3. 같은 날 재진입은 복습으로 다시 올리지 않는다(같은 날 반복은 연습 효과 구분이 어려움).
4. 도래한 표현이 없으면 아직 안 해본 표현을 새로 제시.

**1일/3일 수치는 연구에서 도출한 값이 아니다.** §10의 spacing 근거은 "간격을 두면 유리"를 지지할 뿐 아동·어휘 회화 최적 간격은 정해주지 않는다. 파일럿 후 조정한다.

**구현 반영 메모(2026-10-04, 독립 리뷰 finding 5 — 코드가 기준)**: 실제 구현(`src/utils/situation/situationStore.js`)은 위 초안과 다음이 다르다. 키는 기존 localStorage 접두 관례에 맞춰 `paulEasyVoca_situationRecall_<students.id UUID>`; 레코드는 표현별 `{ lastPracticedDate, sessions[] }` 하나로 통합하고 `sessions[]` 원소가 `{date, scene, stage:'recall'|'transfer', hintLevel:0..3, selfReport:'can'|'hard'|null, recorded}`(최근 10개)를 담아 `selfReports[]`/`hintUsed[]` 두 배열을 대체한다. 자기 보고 값 `'ok'`는 UI 문구("말할 수 있었어요")와 맞춰 `'can'`으로 저장한다. 3일 규칙은 `stage==='recall'` 세션의 마지막 두 건만 본다(같은 날 recall+transfer 한 쌍으로 켜지지 않음). 아무 상호작용(힌트·자기 보고·녹음) 없이 "다음"만 누른 단계는 세션을 남기지 않는다. 의미(완료 플래그 없음·UUID 키·휴리스틱 수치)는 초안 그대로다.

**교사 증거**: 힌트 깊이(`maxHint`), 자기 보고 값, 녹음 시도 여부(Blob 유무는 저장하지 않고 "시도했음" 플래그만 선택 기록). **완료 플래그는 두지 않는다.** 로컬 저장이라 교사 열람은 학생 기기 화면 확인이나 수업 중 관찰로만 가능(후속 서버 동기화 별도).

## 8. 접근성·아동 UX

- 모든 버튼에 텍스트 라벨(이모지는 보조). 아이콘 단독 버튼 금지, `aria-label` 한국어.
- 그림 `alt`는 §3 상황 문장. recall 단계에서 alt가 정답 EN을 노출하지 않도록 한국어 상황 설명만 쓴다(KO 뜻을 직접 쓰지 않는다 — "인사해요"는 상황 묘사이므로 허용하되 표현 문구는 포함 금지).
- 단계 전환 시 포커스를 화면 제목 또는 그림 영역으로 이동, `role="status" aria-live="polite"`로 단계 안내.
- `prefers-reduced-motion`: 전환 애니메이션/펄스는 `motion-safe:` 접두사로만. 기본 정적.
- 색만으로 구분하지 않기: 자기 보고 두 버튼은 라벨 + 아이콘(🙂/🌱) 모두 사용, 힌트 버튼은 `💡 힌트 n` 번호 표기, 힌트 영역과 말하기 영역은 구획선/간격으로 분리.
- 힌트로 드러난 텍스트는 접근성 트리에도 그때서야 나타나야 한다(`hidden` 렌더링 금지: 조건부 마운트).
- 임시 배지는 텍스트("임시 그림")를 포함해 스크린 리더에도 읽힘.

## 9. 검증 계획

**단위(node 하네스, 신규 verify 스위트 등록)**
- 스케줄러: 날짜·자기 보고 입력으로 복습 대상 계산(1일/3일 분기, 같은 날 제외, 미보고 처리).
- 레코드 reducer: 자기 보고/힌트 추가, 최근 10개 절삭, 학생 UUID별 키 분리.
- 힌트 생성: `Can ___ ___ ___` 등 5개 표현 모두 첫 단어 + 밑줄 길이 검증.

**E2E(Playwright, 기존 합성 마이크 방식 재사용)**
- recall 진입 직후 EN/KO가 DOM에 없음(조건부 마운트) → 힌트 1/2/3 순차로 나타남.
- 자기 보고가 `students.id` UUID 키로 저장되고 다른 UUID 로그인 시 보이지 않음.
- 날짜 mock으로 다음 날 진입 시 복습이 신규 표현보다 앞에 오고 recall부터 시작.
- 모든 임시 장면에서 `scene-temp-badge` 존재, 최종 webp가 있는 장면(향후)에서 없음.
- 요약 화면에 "완료/숙달/점수/별" 문구가 없음(텍스트 부재 단언).
- 모바일 뷰포트(375px)에서 EN 폰트 크기 ≥ 24px, 버튼 높이 ≥ 44px.

**자동화 불가**: 학생이 실제로 떠올려 말했는가, 말의 알아들을 수 있음, 장기 기억 여부, 임시 그림의 학습 효과. 이는 교사 확인표(§7)와 파일럿으로만 판단한다. verify는 마이크 하드웨어가 없으므로 합성 스트림 한계가 있고 `SPEAKING_DESIGN` §1대로 일부는 SKIP이 정직하다.

## 11. 운영자 결정 필요 항목

1. 표현 5개 확정(제안 그대로 vs 교체).
2. 임시 그림 공개 범위: 임시 그림만으로 Preview 학생에게 노출해도 되는지, 최종 그림 납품까지 교사 시연만 할지(§3 약점 4장 포함).
3. 최종 그림 10장 제작 주체/일정(유료 생성 금지 전제).
4. 복습 간격 1일/3일 휴리스틱 승인(파일럿 후 조정 전제).
5. 서버 동기화 여부: 기기 로컬만이면 기기 변경/데이터 삭제 시 이력이 사라짐. 교사가 학생별 결과를 보려면 서버 저장(후속, DDL 설계 필요)이 필요.
6. 자기 보고 문구/아이콘 최종안(중립성 유지, "마스터" 연상 금지).
7. 상황 B 전이 평가를 앱 내 판정이 아닌 교사 관찰로만 하는 데 동의 여부.
8. 보상 연동 불가(farming/숙달 오해 방지) 방침 유지 여부.
