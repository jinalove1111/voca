## 1. 교재 의존 감사 (지시 5 — 먼저 보고)
- **결과: 특정 교재(Let's Smile 포함)에 의존하는 Speaking·Writing 콘텐츠·구조는 없다.** 이 worktree의 모든 브랜치(`git log --all`)·`C:\voca`·다른 worktree(`paul-town-v2`)의 `src`·`docs`·`tests`·`scripts`·`handoff.md`에서 "Let's Smile/lets_smile" 일치 0건. 교재 연계 작업은 이 브랜치에서 **시작된 적이 없다**(삭제·reset할 것도 없음).
- 제품 안에 남아 있는 "교재" 개념은 기존 **Voca(단어) 기능**의 `textbooks`/`units`/`textbook_id`(학원이 쓰는 단어장 교재의 단어 목록·진도)뿐이며, 이는 학원이 자기 교재 단어를 올리는 기존 기능으로 Speaking·Writing 콘텐츠와 무관하다(이번에 변경하지 않음). 기존 Writing Coach MVP 설계(`docs/design/WRITING_PILOT_DESIGN_2026-10-02.md`)의 "교재 단어"도 이 Voca 단어를 뜻한다(교재 문장 복사 금지 규칙이 이미 있음).
- Speaking 이야기 10화·문항 114개·기본 표현 5개·Writing 10문항·주제 6개·핵심 문장·장면 그림은 모두 **이 저장소 세션에서 학습 목표부터 새로 작성**했다(아래 §2 출처 기록). 특정 교재의 대화·지문·문항을 가져오거나 단어만 바꾼 것은 없다.

## 3. 자체 커리큘럼 모델 (`src/utils/curriculum/commGoals.js`)

## 5. 학원별 학습 목표 선택(설계 — 이번 구현은 데이터 모델까지)
- 선생님이 "이번 주는 요청하기"처럼 **목표를 고르면** `itemsForGoal(goalId)`가 기본 표현 + 이야기 문항(회차·레벨 포함)을 돌려준다 → 수업 안내(어느 회차·어느 문항을 연습할지)와 연결. 교재명이 없어도 전체 과정(주제 → 이야기 → 연습 → 한글 보고 말하기 → 쓰기)은 이미 작동한다.
- 저장: 학원별 선택은 새 DB 없이는 기기 로컬(QA) → 운영자 승인 시 기존 `classes`/학원 설정 테이블에 `selected_goal_ids`(JSON) 컬럼을 추가하는 마이그레이션(멱등, GRANT 포함)으로 — **이번 범위 밖**, 설계만.
- 화면(다음 단계): 관리자 화면에 "학습 목표" 선택 패널(13개 체크), 학생 Speaking 주제 화면에 "이번 주 목표" 띠로 선택된 목표의 문항을 앞에 보여 주기. 교재별 상세 매핑·교재명·로고 표시는 하지 않는다.
